# CLAUDE.md

Codebase index for `single-image-super-resolution`. Read this first.

## Project overview

PyTorch Lightning framework for reproducing Single-Image Super-Resolution (SISR) papers. Training is driven by `LightningCLI` against a generic `SRLightning` module + `SRDataModule`, so the same command trains any SR architecture — only the YAML changes.

SRCNN is fully wired (model + dataset + config). SRResNet has the model class only — no dataset / training entry yet (triage P3).

Active branch: `reimplement-1`.

## Module map

### `sisr/utils.py`
- `LMDBCache` — checksum-validated LMDB cache; rebuilds when source manifest changes.
- `LMDBCacheBuildContext` — passed to a user `build_fn`; exposes `write_batch()` and `parallel_build()` (ProcessPoolExecutor with sliding-window submission).

### `sisr/training/`
Re-exported from `sisr.training` for short YAML class_paths (e.g. `sisr.training.SRLightning`).

- `SRLightning` (in [lightning_module.py](sisr/training/lightning_module.py)) — generic Lightning wrapper. Takes any `torch.nn.Module` as the inner model. Owns loss / per-Conv2d optimizer groups / scheduler / RGB-Y-YCbCr colorspace handling / PSNR (single + multi-channel) + SSIM metrics.
- `SRDataModule` (in [datamodule.py](sisr/training/datamodule.py)) — generic Lightning DataModule. Constructor takes dataset *kwargs* (instantiated lazily in `setup()` so LMDB cache builds defer to subcommand dispatch) plus the dataset *classes* (so different architectures swap pipelines via YAML). Exposes `benchmark_names: list[str]` for callback auto-discovery.
- Callbacks (in [callbacks.py](sisr/training/callbacks.py)):
  - `BenchmarkImageLogger` — logs LR|SR|HR strips and per-image PSNR/SSIM to TensorBoard for each benchmark loader. Auto-discovers `dataloader_mapping` from `trainer.datamodule.benchmark_names` if not supplied.
  - `GradNormLogger` — logs total gradient L2 norm per backward.
  - `WeightHistogramLogger` — re-exported but not used in the default template.
  - `SRCheckpoint` — `ModelCheckpoint` preset for SR metrics.

### `sisr/cli.py`
- Thin `LightningCLI(model_class=SRLightning, datamodule_class=SRDataModule)` wrapper. Adds Windows `freeze_support()`. ~25 lines.

### `sisr/datasets/srcnn.py`
- `TrainDataset` — sliding-window patch extractor with LMDB caching; LR generated by blur → bicubic-down → bicubic-up. SRCNN-style.
- `ValidationDataset` — full-image LR/HR pairs generated on the fly (same blur→down→up). SRCNN-style; other architectures (e.g. SRResNet) will need their own pipeline under `sisr/datasets/`.

### `sisr/models/srcnn/`
- `SRCNN` — 3-conv arch (feature extraction → non-linear mapping → reconstruction); `padding ∈ {valid, same}` and optional output clamping. See [sisr/models/srcnn/model.py](sisr/models/srcnn/model.py).

### `sisr/models/srresnet/`
- `SRResidualBlock`, `SRUpsampleBlock`, `SRResNet` — defined in [sisr/models/srresnet/model.py](sisr/models/srresnet/model.py). No `__init__.py`, no matching dataset / training entrypoint. See triage P3.

## Training workflow

1. Copy [templates/config.srcnn.template.yaml](templates/config.srcnn.template.yaml) → your config (e.g. `configs/srcnn-x3.yaml`) and edit the `TODO`-marked paths. One file holds everything (model, data, trainer, callbacks, loggers).
2. Run:
   ```
   python -m sisr.cli fit --config configs/srcnn-x3.yaml
   ```
   Useful flags (all native LightningCLI):
   - `--print_config` — dump the resolved config and exit (replaces the old `--dry-run`).
   - `--trainer.max_steps=500000`, `--model.lr=1e-3`, `--data.train_dataset.subimg_size=33` — dot-notation overrides (replaces the old `--set k=v`).
   - `--help fit` — see every available knob.
3. New architecture? Copy the SRCNN template, swap `model.model.class_path`, point `data.train_dataset_class` / `val_dataset_class` at the new pipeline, and edit the per-experiment knobs.
4. Outputs land at `<save_dir>/<name>/<version>/`:
   - `checkpoints/` — `.ckpt` files (filenames driven by `SRCheckpoint`)
   - `metrics.csv` — CSV logger output
   - `events.out.tfevents.*` — TensorBoard scalars + benchmark image strips
   - `hparams.yaml` — flattened hyperparameters
   - `config.yaml` — saved by LightningCLI (full resolved config used for the run)

## Data conventions

- HR images live under `data/<dataset>/` (one file per image, any Pillow-readable format).
- Expected datasets out of the box: `DIV2K_train_HR`, `DIV2K_valid_HR`, `Set5_HR`, `Set14_HR`.
- LMDB caches live under `cache/<dataset>/.lmdb_cache` (or wherever `cache_dir` points). Cache validity is enforced via SHA-256 over the file manifest (name + size) plus the dataset hyperparameters; mutating any of these triggers a rebuild on next load.
- All HR is loaded as RGB by the dataset. Colorspace selection happens later in `SRLightning` (see below).

## Config conventions

LightningCLI / jsonargparse format — every component uses `class_path` + `init_args`. Top-level YAML keys:

- `model` — `SRLightning` init args. The inner model is `model.model` with `class_path: sisr.models.<arch>.<Class>`.
- `data` — `SRDataModule` init args:
  - `train_dataset`, `val_dataset`, `benchmark_datasets` — kwargs forwarded to the dataset classes.
  - `train_dataset_class`, `val_dataset_class`, `benchmark_dataset_class` — class paths (defaults: `sisr.datasets.srcnn.TrainDataset` / `ValidationDataset`).
  - `train_dataloader_kwargs`, `val_dataloader_kwargs`, `benchmark_dataloader_kwargs`.
- `trainer` — full `Trainer(...)` surface, including `callbacks` and `logger` lists of `{class_path, init_args}`.
- `seed_everything` — seeded by LightningCLI before instantiation.

One self-contained YAML per experiment — no layering. Per-architecture templates live alongside each other under `templates/`.

## Colorspace handling

`SRLightning` supports three working colorspaces via `model_colorspace`:

- `RGB` — model trains on all 3 channels directly.
- `Y` — extract luma (Y from YCbCr), train on that, recombine with original Cb/Cr at validation for RGB metrics.
- `YCbCr` — train on full YCbCr, convert back to RGB at validation.

The dataset always serves RGB; conversion is centralized in [sisr/lightning_module.py](sisr/lightning_module.py) at `_rgb_to_ycbcr` / `_ycbcr_to_rgb` / `_extract_model_input` / `_reconstruct_sr_rgb`. The conversion uses BT.601 coefficients (ITU-R Rec. BT.601-7) — see triage P5: those constants need to be lifted to module-level and commented in code.

When `padding='valid'`, HR is center-cropped to match the SR spatial size before loss/metrics; `BenchmarkImageLogger._pad_to_match` zero-pads LR/HR strips so they line up visually with the (smaller) SR output.

### P1 — Confirmed bugs

> SRCNN supports only **RGB / Y-only / YCbCr** training. The dataset stores HR as RGB; colorspace selection is the Lightning module's job. The `channels` param on the datasets is misleading because it currently exposes Pillow modes ('RGB' / 'L'), and 'L' is not a target colorspace.
